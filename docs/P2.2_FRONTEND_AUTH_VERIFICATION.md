## 交付行为

- 页面上方可输入、更换或清除原始 ServiceAccount Token；输入框不回显已应用的凭据。
- Token 仅保留在页面内存，路由切换可继续使用，刷新页面后需重新输入。
- 普通 API 和日志 SSE 通过 Authorization 请求头携带 Token；不使用 URL 参数或浏览器持久化存储。
- 401 展开认证输入提示；403 提示权限不足，503 提示服务不可用，保留当前凭据。
- 更换或清除 Token 取消旧请求、关闭旧日志连接并重新加载当前视图，不自动重试写操作。
- 日志使用 fetch 读取原有 SSE；支持分块 UTF-8、CRLF、空行和多行数据，正常 EOF 保留已收到的日志。

- `web/tests/authentication.test.js`：10 个测试通过，覆盖匿名访问、全部业务 API 的认证头、更换/清除、无效输入、401/403/503、迟到响应、SSE 解码与取消。
- `cd web; npm test`：16 个测试通过，包含原有 6 个 DAG 布局测试。
- `cd web; npm run build`：通过；原有 Dashboard 大包提示仍存在。
- `go test ./internal/api ./internal/auth ./internal/api/middleware -count=1`：通过；设置本地 KUBEBUILDER_ASSETS，包含真实 TokenRequest/TokenReview 与日志流测试。
- 完整 Go 流水线：build → vet → controller-gen → build → 全量 `go test ./... -count=1` 通过；生成文件无内容差异，`git diff --check` 通过。
- 浏览器使用构建产物和本地模拟 API：未认证仪表盘收到 401 并显示 Token 输入；应用模拟 Token 后，仪表盘、任务列表与日志正常显示。
- 实时日志持续超过 10 秒，未被普通请求超时截断；清除 Token 后服务端确认活动流为 0，旧连接已关闭。
- 日志接口的 401 展开认证提示，503 显示服务不可用且保留 Token；刷新页面后显示「未设置 Token」。

浏览器验收使用合成凭据和模拟日志；真实 TokenReview 与服务端日志取消由现有 Go 测试独立验证，本轮未进行真实集群或容器部署验收。
