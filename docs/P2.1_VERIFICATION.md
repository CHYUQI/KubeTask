## 浏览器与真实控制面联调

使用临时 envtest（etcd + kube-apiserver 1.35.0），启动生产代码中的两个 Controller、Gin Router 和 `web/dist`。Workflow 通过 HTTP API 创建，子 Task 与 Job 均由 Controller 创建；仅 Job 的成败状态由测试程序注入。浏览器访问同端口的实际静态页面与 API。

- 列表进入详情、状态筛选、分页及空结果已验证；分页和错误展示在前两步使用模拟 API 检查，本轮列表/详情使用真实 API。
- `build → test / lint → deploy / notify`：build 成功后并行启动 test、lint；lint 失败后 deploy 被跳过；notify 等待 test 到达终态后启动。
- 页面同时展示过 `Succeeded / Running / Failed / Skipped / Pending` 五种节点状态，失败分支连线为虚线。
- Job 状态经 Task Controller 和 Workflow Controller 同步后，浏览器自动刷新；选中节点和缩放比例保持不变。
- 正常链路全部成功后，失败分支记为 Skipped，Workflow 到达 Succeeded；失败链路即使通知成功，Workflow 仍为 Failed。
- 节点选择、子 Task / 日志链接、缩放、适应窗口、大图滚动及第 50 个节点的选择可用。
- API 拒绝未知依赖（400）；绕过 HTTP 直接写入的非法 CR 仍可在详情查看：缺失依赖显示「缺失节点」，循环依赖保留全部节点和边，并显示后端校验原因。
- 通过临时代理模拟后端 503：自动刷新失败时保留上次数据及选中节点，恢复服务后继续刷新。
- 通过代理请求记录验证：关闭自动刷新后不再轮询，Workflow 终态停止轮询。
- 删除本次创建的 Workflow 后，API 最终返回 404，其子 Task 全部清理。

临时联调程序、代理与 envtest 在验收后停止并清理，不属于部署产物。

## 2026-10-13 minikube 真实集群补充验收

环境：minikube v1.39.0，Hyper-V，独立 profile/context `kubetask-p21`，单节点 2 CPU / 3072 MB，Kubernetes v1.35.0，containerd v2.3.4。节点及系统 Pod 均正常运行。启动前启用了缺失的 Hyper-V PowerShell 管理模块，无需重启；下载使用国内镜像源并关闭可选 preload。

本轮 KubeTask 作为 Windows 本机程序运行，通过独立 kubeconfig 连接 minikube，Web UI 与 API 同在 `127.0.0.1:18080`。所有 Job / Pod 均在真实节点执行，没有注入状态。

可复跑脚本：[workflow_minikube.ps1](../test/integration/workflow_minikube.ps1)。需先安装 CRD，并启动连接到该 context 的 KubeTask 服务：

```powershell
.\test\integration\workflow_minikube.ps1 `
  -ApiBaseUrl http://127.0.0.1:18080 `
  -KubeContext kubetask-p21
```

脚本使用唯一名称，通过 API 创建工作流，并核对 API / kubectl 对象 UID，确保指向同一集群。默认会清理本次资源；`-KeepResources` 可供临时浏览器检查。

| 场景 | 实测结果 |
| --- | --- |
| 成功链路 | build / test / lint / deploy 成功，notify 为 Skipped，Workflow 为 Succeeded |
| 失败链路 | lint 的容器实际退出码为 7，deploy 为 Skipped，notify 成功，Workflow 保持 Failed |
| 实际执行与并发 | 每个工作流执行 4 个 Pod，共 8 个；其余容器退出码为 0；轮询期间运行节点数不超过 maxParallel=2 |
| 实际日志 | 8 个 Pod 的输出经 SSE API 返回，逐个匹配 `SMOKE-<节点名>` |
| 前端 DAG / 日志 | 成功及失败 DAG 状态、节点跳转、成功和失败 Pod 的日志均可查看 |
| 删除清理 | 默认脚本复跑通过；Workflow、子 Task、Job、Pod 均清理完成 |
| 本轮回归 | 前端 6 个测试、前端构建、Go build/vet/controller-gen/全量测试通过 |

真实日志联调发现并修复了一个前端问题：非跟踪 SSE 正常 EOF 被 `EventSource.onerror` 当成断线，导致已收到的日志被隐藏。`TaskLogs.vue` 现在根据连接是否已建立及本次请求的 follow 参数识别正常结束；使用实际成功 / 失败 Pod 复验后，日志保留显示且没有错误提示。后端 SSE 响应结构保持不变。

测试完成后清理测试资源、关闭本地 KubeTask，并停止 minikube 以释放内存；profile 保留供后续重启。Dockerfile 多阶段构建和 Helm 容器部署仍未在本轮执行。
